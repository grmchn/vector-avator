# ベクター立ち絵の部品仕様

ベクター立ち絵のレンダラー（`src/renderers/vector/`）が読むキャラクターデータの仕様です。
新しいキャラは、本書に沿って部品を描き、`vector.json` に骨格の目印を書けば、共通の骨格テンプレートで動きます。
作業の流れは `../SKILL.md` を参照してください。

## 1. ファイル構成

キャラごとに `public/characters/<キャラID>/vector/` に置く。

| パス | 内容 | 作る人 |
|---|---|---|
| `ref/front.png` | 画風を変換した正面の立ち姿（1024×1536）。部品を描く主な参照 | Codex imagegen（SKILL.md の 2） |
| `ref/sheet_turnaround.png`・`ref/sheet_face.png` | キャラクターシート 2 枚 | Codex imagegen（SKILL.md の 4） |
| `ref/angle_<度>.png`・`ref/turntable.mp4` | MiniMax H3 の 360 度回転動画とコマ（角度の見本。任意） | `turntable.sh`（SKILL.md の 3） |
| `vector.json` | **本体**。全部品のパス、骨格の目印、腕の定義、揺れ物、差分、表情 | Fable 5.2 |
| `build/` | 確認用の書き出し：`character_layers.svg`（Inkscape レイヤー）、`layers/`・`variants/`（部品ごとの SVG） | `check_parts.py` |
| `preview.png` | 通常状態の統合画像 | `check_parts.py` |

`vector.json` は、`art.json`（schema_version 1、`art-json.md`）の上位互換とする。
部品のパスを JSON に直接持つため、レンダラーは 1 ファイルを読めば描ける。`tools/vector/layers/vector_layers.py`（validate・build）もそのまま使える。

## 2. 座標と描き方の共通ルール

- キャンバスは `ref/front.png` と同じ **幅 1024 × 高さ 1536**。右が +X、下が +Y。全部品が同じ座標を使う（部品ごとのローカル座標にしない）。
- 正面の立ち姿（A ポーズ）を、`ref/front.png` と重なる位置・大きさで描く。
- **塗りだけで描く。** `stroke` は `null`、`width` は 0。輪郭線は描画時に自動生成する。眉・閉じた目・口の線のような細い形も、細い閉じた塗りの形として描く。
- 1 つの shape は 1 つの閉じた輪郭（穴なし）。穴や複数の輪郭が要る場合は shape を分ける。グラデーション・透明・マスク・クリップ・`<image>`・フィルターは使わない。パスのコマンドは `M/L/C/Q/Z`（絶対座標）。
- 部品の中の模様（耳の内側、毛の房の段差、スカートのひだ、ネクタイの影）は、同じ部品の中に別の shape として、少し濃い同系色の塗りで描いてよい。広く弱い影 1 段（共通の画風）も同様。
- **自動輪郭線は部品単位で引く**（線を出さない指定は §3.1 の `seamlessWith`・`outline`）。 部品の外形（全 shape の和）のうち、先に描かれた近い色の部品に重なる縁にだけ、部品の内側に線が出る。同じ部品の中の shape どうしの境目には線が出ない。したがって、白一色のキャラでは「線を出したい房」は別部品に、「線を出したくない塊」は同じ部品の shape にする。
- 線は「手前の部品」と「先に描かれた近い色の部品」の組で決まり、間に挟まる部品は考えない。例えば前髪の縁は、顔を挟んだ奥の後ろ髪に対しても線を出す（顔と髪の境の線として働く）。
- 奥の同色の部品（後ろ髪など）は、首振り（§3.5）でずれても手前の部品の外へはみ出さないよう、手前より内側に描く（目安：頭の半径の 7% 程度。髪の多いキャラで約 14px）。
- **顔パーツ（`layer: "feature"`）には自動輪郭線を引かない。** 白目の縁、閉じた目の線、口の線など、顔に必要な線は shape として描く（白い顔に白い白目を置くキャラでは、白目の縁の灰色の輪を白目の部品の奥の shape にする）。
- 房の途中から始まって消える線（毛の房の切れ込み、しっぽの巻き）は、線の色の細い閉じた塗り（先細りの形）を、その部品の shape として描いてよい。色は部品の色を少し暗くした灰色（例：白 `#FBF7F4` に対して `#D9D3D0` 前後）。
- 部品は意味の単位で**ゼロから描く**。元画像の画素の切り抜き、自動トレース、色分けや可視輪郭の当てはめで形を決めない。画像処理は、色の抽出、寸法・座標の測定、重ねての比較に限る。
- 部品単体で表示しても形が成立するようにする。**隠れる部分も補完する**（§5）。
- 左右の `_L`・`_R` は**キャラ自身の左右**とする（VRM の骨名と同じ）。正面図では、キャラの左（`_L`）が画面の右側にある。

## 3. `vector.json` の項目

```jsonc
{
  "schema_version": 1,            // art.json と同じ
  "format": "so-chara-vector/1",
  "character": "usagi",
  "width": 1024, "height": 1536,
  "parts": [ /* §3.1。配列の順が描画順（0 が一番奥） */ ],
  "skeleton": { /* §3.2 */ },
  "arms": { /* §3.3 */ },
  "chains": [ /* §3.4 */ ],
  "parallax": { /* §3.5 */ },
  "headTurn": { /* §3.5.1（省略可） */ },
  "expressions": { /* §3.6 */ },
  "qa": [ /* art.json と同じ。reveal と move を必ず含める */ ]
}
```

### 3.1 部品（`parts[]`）

art.json の項目（`id`、`label`、`parent`、`pivot`、`visible`、`coverage`、`shapes`）に、次を足す。

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | 小文字のスネークケース。左右だけ大文字の `_L`・`_R`。§4 の名前を使う |
| `bone` | 必須 | 動かす骨。共通骨格の骨名（`hips`、`spine`、`chest`、`neck`、`head`、`leftUpperLeg` など。`src/core/skeleton.ts`）か、揺れ物チェーンの id |
| `layer` | 必須 | 首振りの変形の層（§3.5）。体の部品は `body` |
| `group` | 差分のみ | 差分グループ（`eye_L`、`brow_R`、`mouth`、`hand_L`、`sleeve_R` など） |
| `variants` | 差分のみ | その部品が表示される差分の名前の配列。例：白目は `["open","half"]`、半目のまぶたは `["half"]` |
| `clipTo` | 任意 | この部品を、指定した部品の形で切り抜いて描く（虹彩・瞳孔を白目で切り抜くなど）。指定した部品の全 shape の和で切り抜くので、白目の部品に縁の輪の shape を入れると、虹彩は輪の外縁まで見える |
| `color` | 任意 | 自動輪郭線の色の元になる基本色（`#RRGGBB`）。省略時は最初の shape の `fill`。線を消す目的で塗りにない色を書かない（下の 2 項目を使う） |
| `seamlessWith` | 任意 | 線を出さない相手（部品 id、生成した腕は `arm_L`・`arm_R`）。どちらの部品に書いても同じ。例：耳と頭、胴と脚が線なしでつながるキャラ |
| `outline` | 任意 | `false` でこの部品は線を出さない（継ぎ目を覆うための部品など） |
| `halo` | 任意 | `true` で、この部品の直前に部品自身の外側の輪郭線（`vOuter` と同じ太さ・色）を描き、後ろの部品との境目の線はこれで出す（内側の線は引かない）。太い黒線のキャラの頭など、下端の線を体の上にも角から角まで出したい部品に使う。`vOuter` が切れているときは何もしない |
| `outer` | 任意 | `false` で、この部品を太い外側の輪郭線（`vOuter`）の対象から外す。頭の上に出す小物（`prop_*`）など、外形の黒線を付けたくない部品に使う |
| `pivot` | 必須 | 回転の支点。腕・脚は付け根、耳・髪の房は根元、手は手首 |
| `visible` | 必須 | 通常状態（表情：通常、目：開、口：閉、手：開き）で表示するか |
| `coverage` | 必須 | 補完した範囲を具体的に書く（「前髪の下の額まで」など）。隠れない部品は「補完不要」と書く |

### 3.2 骨格の目印（`skeleton`）

正面の A ポーズでの関節の位置（キャンバス座標）。キャラごとの骨の長さは、ここから求める。

| キー | 内容 |
|---|---|
| `hips` | 骨盤の中心（脚の付け根の高さ） |
| `chest` | 胸の中心（肩の高さより少し下） |
| `neck` | 首の付け根（胴の上端の中央） |
| `head` | 頭の回転の支点（あごの下、首の上端） |
| `head_center`・`head_radius` | 頭の本体（耳・髪のふくらみを除く）の中心と、横・縦の半径 `[rx, ry]`。顔パーツが乗る球の大きさなので、髪の多いキャラは顔の肌の幅を基準にし、髪のドームより小さくてよい |
| `shoulder_L/R`・`elbow_L/R`・`wrist_L/R` | 肩・肘・手首の中心。腕の骨の長さ（上腕 = 肩〜肘、前腕 = 肘〜手首）になる |
| `hip_L/R`・`ankle_L/R` | 脚の付け根と足首 |

### 3.3 腕の定義（`arms`）

腕は絵を持たず、描画時に生成する。左右それぞれに次を書く。

```jsonc
"arms": {
  "L": {
    "width": { "shoulder": 52, "elbow": 42, "wrist": 34 },   // 正面から見た腕の太さ（px）
    "bands": [                                              // 腕に沿った色の帯。t は肩 0 → 手首 1
      { "from": 0.0, "to": 0.55, "color": "#FFFFFF" },
      { "from": 0.55, "to": 1.0, "color": "#22305E" }
    ],
    "shade": { "color": "#E2E4EA", "side": "under", "ratio": 0.32 }, // 影の帯：色、側（under = 腕の下側／体側）、太さの割合
    "attach": "torso",                                      // 通常時、腕をこの部品の直前（裏）に描く
    "seamlessHand": false,                                  // true: 手首（手と腕の境目）に線を出さない
    "rootGap": 0                                            // 肩の点からこの半径（px）以内では、手前の部品が腕の上に線を出さない
  },
  "R": { ... }
}
```

- `shade.ratio` を 0 にすると影なし。色の帯が 2 つ以上あるときは、影の色は帯ごとに帯の色を少し暗くして自動で決める（`shade.color` は帯が 1 つのときだけ使う）。
- 帯の境目は正確な位置で切り替わる（標本点に合わせる必要はない）。自動輪郭線の「近い色」の判定も帯ごとに行う（紺のアームカバーと紺のスカートの間には線が出る）。
- 帯は上腕と前腕で別々に作る。肘をまたぐ帯は肘の丸い端まで塗るので、肘を深く曲げても切れ目は出ない。上腕と前腕が別の層に分かれたときは、それぞれ自分の区間の帯だけを描く。腕がカメラの方を向くと、帯の境目は奥の側へふくらむ楕円の弧になる（腕の輪の見え方）。帯が 2 つ以上あり、肩 0 から手首 1 まですき間なく並んでいるときは、帯の下に下地を塗らない（下地の縁が明るい細い線として出るため）。すき間があるときは、最初の帯の色で下地を塗る。
- 骨の長さだけを目印から測る。ビューアの姿勢（気をつけ等）は共通のポーズデータで決まり、参照画像の A ポーズの腕の角度は使わない。
- `attach`：腕（通常時）を、この部品の直前に描く。胴の手前・胸元の毛の裏に腕を通すキャラは `"chest_fur"` のように、胴より手前の部品を指定する。腕が胴の前方へ大きく出たとき（奥行きで判定）は、全部品の手前に描く。

### 3.4 揺れ物チェーン（`chains[]`）

```jsonc
{ "id": "ear_L", "bone": "head", "parts": ["ear_L", "ear_L_inner"],
  "root": [600, 330], "tip": [700, 40], "segments": 4,
  "stiffness": 0.6, "damping": 0.35, "gravity": 0.15 }
```

- `root`→`tip` の折れ線を `segments` 個の節に分け、部品のパスの点を節に重み付きで割り当てて曲げる。
- `gain`（任意、既定 1）は、動きへの反応の強さをチェーンごとに変える倍率。
- 胴の揺れ物（ネクタイ・リボンなど）は、`bone` を `chest` にして、付け根を結び目のすぐ下に置く。部品の `bone` はチェーンの id にする（例：ネクタイの `tie`）。
- `stiffness`・`damping`・`gravity` は 0〜1 の目安値（レンダラーで物理量に換算する）。目安：耳・ツインテールは柔らかく揺れるのが魅力なので、`stiffness` 0.5〜0.75、`damping` 0.3〜0.4（行き過ぎて戻る）。
- 頭のチェーンは、頭の移動・傾きに加えて、首振りの速さ（横の遅れ）と、うなずき・呼吸・跳ね（長さの伸び縮み）でも揺れる。しっぽ（`hips` のチェーン）は、待機中もゆるく揺れる（`vWag`）。

### 3.5 首振りの変形（`parallax`・`headTurn`）

頭の左右回転（±30° まで）と上下は、正面の絵 1 枚を Live2D のように変形して表す（`src/renderers/vector/head.ts`）。
部品の `layer` で、変形の種類が決まる。

| 層 | 変形 | 部品 |
|---|---|---|
| `feature` | **剛体**。部品（差分グループ）の左右の端が顔の球面に乗って動き、その間は横に縮むだけで中身は歪めない。向いた側の目は細く、反対側の目は少し広くなる。虹彩・瞳孔（`clipTo` 付き）は白目の中でさらに向いた方へ転がる。口（group `mouth`）は鼻の列に乗り、鼻の下を保つ | 目・眉・鼻・口・頬 |
| `head` | **顔の球面の点ごとの変形**。`feature` と同じ式なので、目が顔の輪郭を追い越さない。顔の球の縁（`head_radius` × `headTurn.radius`）では動かない | 頭の本体（顔の肌） |
| `hair_front`・`hair_side` | **殻（点ごとの変形）**。中央がいちばん動き、頭全体の縁（`headTurn.reach`）で 0 になる（縁で傾きも 0）。向いた側は縁の手前で縮み、反対側は広がる。頭頂に近いほど動きが小さい（球の上は動かない） | 前髪、髪飾り、横髪、頭頂の毛 |
| `hair_back`（負の値） | 全体が逆方向へずれる | 後ろ髪 |
| `ear`、頭の揺れ物チェーンの部品 | **付け根での剛体**。付け根（チェーンの `root`、チェーンでなければ `pivot`）の位置で頭に追従し、左右の付け根は頭の中心へ少し寄る。向いた側は横に細く、反対側は広くなる。2 つめ以降の shape（内耳など）は、向いた方へ少しずれる（部品の最初の shape で切り抜く） | 耳、うさ耳のツインテール |
| `body` | — | 体の部品（首振りの変形に入らない） |

頭の部品すべてに、向いた方への小さな移動（`headTurn.shift`）が加わる。

`parallax` には、層ごとの動きの量を書く。単位は「層の中央が動く量 ÷ 頭の半径」で、首を 90° 振ったときの値（30° ではその半分）。正は向いた方向。

| 層 | 既定 | 目安 |
|---|---:|---|
| `hair_back` | -0.10 | 手前の髪より内側に描いた余白（§2）を超えない量にする。超えると、前髪の縁の近くに後ろ髪が細くはみ出し、輪郭線が二重に見える |
| `ear` | -0.04 | 耳は頭の後ろ寄りに付くので、わずかに逆へ |
| `head` | 0.45 | 顔の肌が頭の輪郭そのもののキャラ（仮うさぎ）は 0.45 前後。顔が髪・毛の中の「窓」になっているキャラは `feature` に近づける |
| `feature` | 0.75 | |
| `hair_side` | 0.65 | `feature` より少し小さく（向いた側の反対で頬が広く見える） |
| `hair_front` | 0.85 | `feature` より少し大きく（前髪は顔より手前） |

#### 3.5.1 調整値（`headTurn`、すべて省略可）

| キー | 既定 | 意味 |
|---|---:|---|
| `radius` | 1 | 顔の球の半径（`head_radius` に対する倍率）。顔が頭（毛の玉）に対して小さく描かれているキャラは 1 より大きくする |
| `reach` | 自動 | 頭全体の縁 `[半幅, 中心から上, 中心から下]`（px、`head_center` から）。省略時は、頭の固定部品（`feature`・`ear`・揺れ物を除く）の外接から求める |
| `shift` | 0.08 | 頭全体の移動（頭の半径に対する割合、90° のとき） |
| `rimFalloff` | 1 | 顔の変形を縁へ向けて弱める指数（`cos^n`、1 以上） |
| `domeFloor` | 0.35 | 頭頂で残る動きの割合（0 で頭頂は動かない） |
| `irisRoll` | 0.2 | 虹彩の転がり（白目の幅に対する割合、90° のとき）。虹彩が大きい目は小さくする |
| `pupilDepth` | 1.35 | 瞳孔は虹彩より手前（角膜のふくらみ）にあるとみなし、虹彩の何倍動かすか。虹彩の板が回るだけに見えないようにする |
| `irisSqueeze` | 1 | 転がったときの虹彩・瞳孔の横（上下）の縮み（1 = 転がり角の cos） |
| `lidFollow` | 0 | 虹彩が下へ動いたとき（下向きの首・視線・マイクロサッカード）、上まぶた（`eye_*_lash`・`eye_*_half`・`eye_*_lid_half`）を虹彩の下への移動量の何倍ついていかせるか。白目に縁の線がなく、まつ毛だけがまぶたの線になるキャラ（ツインテールのキャラ：1）で使う。0 のままだと、下がった虹彩の上端の縁がまつ毛に接して全部見え、虹彩がまぶたより手前にあるように見える。白目に縁の線があるキャラ（毛の多いキャラ）は 0 のまま |
| `noseDepth` | 1.1 | 鼻の出っ張り（鼻だけ動きを大きくする倍率） |
| `earSqueeze` | 0.3 | 向いた側の耳が細くなる割合（90° のとき） |
| `earIn` | 1 | 耳の付け根が頭の中心へ寄る量（1 で、円柱の横に付いた点と同じ） |
| `earInner` | 0.08 | 耳の 2 つめ以降の shape のずれ（耳の幅に対する割合、90° のとき） |
| `pitchGain` | 1 | 上下の動きの倍率 |

値は、ビューアの URL で試してから `vector.json` に書く：`vPar=feature:0.8,head:0.6`、`vTurn=radius:1.3,irisRoll:0.14`。首振りの上限は `vMaxYaw`（既定 30）。

確認の観点：±30° で、(1) 目・頬が顔の輪郭や横髪の外へ出ない、(2) 髪の縁に二重の輪郭線が出ない、(3) 耳・ツインテールの付け根が頭から離れない、(4) 半目・閉じ目・口の差分でもずれない。


### 3.6 表情（`expressions`）

表情ごとに、各差分グループで使う差分を書く。口は、話していないときの形。

```jsonc
"expressions": {
  "normal":   { "eye": "open",  "brow": "normal",   "mouth": "closed" },
  "smile":    { "eye": "smile", "brow": "smile",    "mouth": "smile" },
  "surprise": { "eye": "open",  "brow": "surprise", "mouth": "surprise" },
  "trouble":  { "eye": "open",  "brow": "trouble",  "mouth": "trouble" }
}
```

`eye` は `eye_L`・`eye_R` の両方、`brow` は `brow_L`・`brow_R` の両方に適用する。

まばたき（自動・モーションのキー）の受け方は、表情ごとの `blink` で決める。表情が専用の目を使うとき、数コマだけ普通の半目・閉じ目に替わると、一瞬だけ普通の顔に戻ったり、閉じた目が一瞬開いたりして見えるためである。

| `blink` | 動き | 省略時の既定 |
|---|---|---|
| `full` | 半目・閉じ目の両方を出す | `eye` が `open` の表情 |
| `closed` | 閉じ目だけを出す（半目のコマは表情の目のまま） | `eye` が `open`・`smile` 以外の表情（困りの目など） |
| `none` | まばたきを受けない（表情の目のまま） | `eye` が `smile` の表情（∩ 型の目は閉じているため） |

通常は省略してよい。既定と違う動きにしたい表情にだけ書く（例：`"smile": { "eye": "smile", "blink": "full", ... }`）。

#### 手の形 8 種

説明動画で必要な手の形である。モーション JSON の `hands`（`{"L": "peace"}`）か、URL の `hand=`（両手に固定）で指定する。指定がないときは、手のひらの向きから自動で選ぶ（下記）。

| 差分名 | 使う場面 | 描き方の要点 |
|---|---|---|
| `open` | 待機、話しながらの手（既定で表示） | **軽く開いたリラックス形**。全開にしない。手の甲側 |
| `palm` | 「ここ」「ストップ」「説明します」 | 手のひら側をカメラに向ける。`open` と一目で見分けがつく（親指の位置、手のひら側の肉づき・シワ・パッド）。手の甲側との違いは `open` と `palm` で表す |
| `palm_up` | 「こちらです」「差し出す」 | 手のひらを上にして差し出す形。**前腕が横向きのとき、盆のように見える細い形**（幅方向を縮め、指先がやや上へ反る）。親指は奥の縁（+x）に立つ。ほかの形と同じく手首から真下に描く |
| `point` | 指差し | 人差し指を伸ばし、ほかの指は握る |
| `point_front` | カメラへの指差し | `point` が手前を向いた形（指が縮んで見え、指先が正面を向く）。手の向きがカメラに近いとき、`point` の代わりに使う |
| `fist` | 強調 | 握りこぶし。`open` との差を大きく（指が折れて丸まる） |
| `peace` | 数字の 2、ピース | 人差し指と中指を立てる。数字の 1 は `point` で代用する |
| `thumbs_up` | OK、いいね | 握った手から親指を立てる |

数字の 3 以上、OK サイン、半開き・握りかけなどの中間の形は作らない。

**親指・人差し指の側（左右の規則）。** 手の絵は `_L` を基準に描き、`_R` は左右反転する。A ポーズの `_L` は画面の右に腕が出る（体は画面の左側）。手の甲側の絵（`open`・`point`・`fist`）は、親指・人差し指を体の側（−x）に描く。手のひら側の絵（`palm`・`palm_up`・`thumbs_up`）は、親指を反対側（+x）に描く。`point_front` は、手首をまっすぐにしてカメラを指差す自然な手で、親指は +x の縁に巻きつく。`thumbs_up` の親指が +x なのは、前腕が体の外へ向くとき親指が上を向くため。

**自動の左右反転（レンダラー）。** `point` は人差し指が体の側（横向きのときは上）に来るよう、`thumbs_up` は親指が上に来るよう、描画を左右反転する（`mirrorDot()`・`thumbUpSide()`、`src/renderers/vector/handShape.ts`）。前腕が真下・真上を向いて上の側が決まらないときは、直前の選択を保つ。`thumbs_up` は親指が横を向くので、前腕を真上へ立てた姿勢では「いいね」に読めない。モーションでは前腕を横〜斜めにする。

**描き方の注意。**

- 手は、腕がカメラに向くと、手首→指先の方向を最小 0.6 倍まで縮めて描かれる。突起・指は気持ち長めに描く。
- `arms.*.seamlessHand` が true のキャラでは、手は前腕の下に描かれ、前腕の丸い端（半径は `arms.width.wrist` の半分）が、手首からその距離以内を隠す。**見分けに使う印（指の分かれ目、握った指の折れ線、親指、パッド）は、手首から手首の太さの半分より外に描く。** 毛の多いキャラは、元の大きさのままだと印が隠れたので、手首→指先を 74 → 88〜110 px に伸ばした。手の長さの目安は、手首の太さの 0.9〜1.2 倍。
- 白い手が白い部品（耳・髪・体）に重なると、手の外形の輪郭線が出ない。ツインテールのキャラは耳が体の横に垂れるので、腕を横へ出すと手が耳に重なり、内側の線だけで読むことになる。手が体の前（胸の前）に来る動作では読める（`hands_demo_chest`）。
- `hand=point_front` の固定はできない（`point_front` は `point` が手前を向いたときの自動選択）。確認は、手がカメラを向く指差しの動作（`reach`・`point_path`）で行う。

**手のタイプ。** 手の絵のタイプは 3 つある。部品の ID・差分名・向き（手首から真下）は同じで、形の指針だけが違う。キャラにはテンプレートを適用して載せる（下記）。

| タイプ | キャラ | 描き方（テンプレートの実物） |
|---|---|---|
| 素体（`human`） | 基準のみ | 5 本指の人間の手。8 種の構図・見える面・線の基準。手の甲側（`open`・`point`・`fist`）は内側の線なし、手のひら側（`palm`・`point_front`・`peace`・`thumbs_up`）は握った指の先の線あり、`palm_up` は小指の縁。`thumbs_up` は 👍 を 90° 回した形（握った指の巻きは親指に垂直）、`peace` は薬指・小指を手のひらの下へ握り込み親指が小指の側まで渡る、`point_front` は人差し指の腹が拳の左下から外へ出て親指は内側にしまう |
| けもの型（`beast`。| 毛の多いキャラ・ツインテールのキャラ | 親指＋短い指 3 本（計 4 本）。指は手の長さの約 1/3 の太く丸いこぶ、手のひらの塊は大きく。面と線は素体と同じ。肉球（`$pad`）はカメラを向いた面にだけ：手のひらの肉球は `palm`・`palm_up` だけ、指先の肉球は伸ばした指（`palm`・`palm_up`・`peace` の V・`thumbs_up` の親指）だけ。握った指の先・折った親指・`point_front` の指先には描かない |
| ミトン型（`mitten`） | 仮うさぎ | 親指＋ひとかたまりの手。指が出るのは `point`（1 本）・`peace`（2 本の V）・`thumbs_up`（親指）・`point_front`（指の腹の丸）だけ。手の甲側は線なし、肉球なし（仮うさぎのシートの手にない）。`palm` は大きく広げたうちわ形（指先に浅い切れ込み 2 つ、親指は斜め下）、`palm_up` は細長い板、`thumbs_up` はコンパクトな拳＋長い親指 |


**手のテンプレート。

| タイプ | テンプレート | 使うキャラ | 元にするもの |
|---|---|---|---|
| 素体（`human`） | `tools/vector/hands/templates/human.json` | （基準。キャラには使わない） | ユーザーが承認した 1 ポーズ 1 枚の見本（`tools/vector/hands/sheets/human_v3/`。MiniMax H3 Image で `open` を画風の基準にそろえた）。Fable は見本に重ねて（`overlay.py`）描き、見本より良くしてよい |
| けもの型（`beast`） | `templates/beast.json` | 毛の多いキャラ・ツインテールのキャラ | 見本の画像なし。Fable が、承認済みの素体のテンプレートと、毛の多いキャラのシートの手（テンプレートの向きに回したもの）から直接デフォルメする |
| ミトン型（`mitten`） | `templates/mitten.json` | 仮うさぎ | 見本の画像なし。Fable が、承認済みのけもの型と、仮うさぎのシートの手から直接描く |

- **作画の担当：** テンプレートの形を描く・直す・消すのは、すべて Fable 5.2 のサブエージェント。親エージェントは依頼文・見本の画像・ラボ・検査・適用ツールを受け持ち、座標を自分で描かない。
- **形ごとの見える面と線（`side`・`lines`）：** タイプごとの表を `tools/vector/hands/types/<タイプ>.json` の `poses` に持ち、依頼文に差し込み、テンプレートの各部品にも書き出す（適用ツールがキャラの部品へ引き継ぐ）。`side` は `back`（手の甲）・`palm`（手のひら）・`edge`（小指の縁）、`lines` は `none`・`pad`・`fingertips`・`fingers`（と `+pad`）。手の甲側は指の線を描かない、手のひら側は握った指の先の線を描く。
- **テンプレートの形式：** `{"type": "human", "wristWidth": 100, "palette": {"base", "line", "pad"}, "parts": [{"id": "hand_L_open", "variant": "open", "side", "lines", "label", "shapes": [{"name", "fill": "$base", "d"}]}]}`。手首の中心が (0, 0)、前腕（手首）の幅 100、指先は +Y。左手 8 種だけを持つ。塗りの色は `$base`・`$line`・`$pad` のトークン。手の大きさは承認した見本のまま（手の長さは手首の幅の約 1.6〜1.8 倍）で、キャラごとの大きさは適用のときに一様な倍率で合わせる。
- **確認ラボ：** `python tools/vector/hands/lab.py <テンプレート> --out <DIR>`。前腕の筒（太さ＝手首の幅、端は丸く、`seamlessHand` と同じに手首の半径以内を隠す）に付けて、拡大（手首 270 px）・等倍（90 px）・全身サイズ（25 px）・シルエット（黒、25 px）と、前腕の向き（下・横・斜め上・真上）を画像にする。`--compare A B C` でタイプを段に並べて比べる。
- **見本との重ね合わせ：** `python tools/vector/hands/overlay.py <テンプレート> <見本のフォルダ>`。見本の前腕の太さ・中心・手首の位置を自動で測り（`calib.json` で上書きできる）、ベクターを半透明で重ねた画像と、手の部分の輪郭の一致率（IoU）を出す。素体の 5 回目は 8 種とも 0.92〜0.96。
- **シルエットテスト：** `lab.py <テンプレート> --quiz <種> --out <DIR>` で、8 種を並べ替えて名前を隠したシルエット（`quiz_large.png`・`quiz_x4.png`）と答え（`quiz_key.json`）を作り、経緯を知らない別のエージェント（Opus 5.5）に `tools/vector/hands/quiz_brief.md` で当てさせる。7 種以上の正答を目安とする。3 タイプとも、最後まで迷われたのは `fist` と `point_front`（自然な `point_front` はシルエットがこぶしに近い。色付きなら指の腹の輪で読める）。
  - 8 種を 1 枚に並べたシートより、**1 ポーズ 1 枚を、テンプレートと同じ向き**（前腕が上、指先が下、左手を体の横に下ろして正面から見た形）で作る。Fable は回転・反転をせず、重ねてなぞれる。
  - 見本は**ユーザーの承認を関門**にする。手として正しいか（手首は 90° 曲がらない、`thumbs_up` の握った指は親指に垂直、`point_front` の指を拳の中央に置くと中指を立てたように見える、など）を先に確かめる。
  - 8 枚の画風（線の太さ・色・前腕の太さ・指の太さ）は 1 枚を基準にそろえる。そろえないと、大きさや指の太さのばらつきがベクターに残る。大きさが合わない見本は、`calib.json` の倍率で合わせる。
  - 画像モデル（Qwen Image・MiniMax H3 Image）は、指の本数を減らす変換（5 本→親指＋3 本）ができない。けもの型・ミトン型の見本を生成すると「素体を白く塗っただけ」になり、新しい情報を足さないので作らない。派生タイプは、承認済みの親タイプのテンプレートと、キャラのシートの手から Fable が直接描く。
  - 合否は、シルエットテスト（AI）とユーザーの目視の両方で決める。シルエットテストは「区別できるか」しか見ないので、手として正しいか・見本どおりかは目視で見る。
- **適用：** `python tools/vector/hands/apply.py <キャラ ID> <タイプ> [--scale S]`。テンプレートを `skeleton.wrist_L` に置き、`arms.L.width.wrist` × 倍率に拡大縮小し、トークンをキャラの手の色に置き換える。右手は `skeleton.wrist_R` で左右反転して作る。`vector.json` の `hand_*` 部品だけを、元の位置で差し替える（冪等。初回の前に `var/vector/<id>/hands_v1/vector.json` へ控えを取る）。倍率の既定値は `SCALE`（仮うさぎ 0.7、毛の多いキャラ 0.85、ツインテールのキャラ 0.8。正面の見本 `ref/front.png` の手と見比べて決めた）。キャラごとに、指の線の色（`COLORS` の `line`。輪郭線より薄くする）、線を外す形（`DROP_LINES`。毛の多いキャラの `peace` は線なし）、形ごとの倍率（`SHAPE_SCALE`。毛の多いキャラ・ツインテールのキャラの平常時の手 `open` は 0.8 倍。ジェスチャー中の手は大きくてよい）を設定できる。
- **袖口のあるキャラ（`wristCap`）：** 手を袖の奥に回したいキャラ（ツインテールのキャラ）は、`arms.*.seamlessHand: true` と `arms.*.wristCap` を組み合わせる。`seamlessHand` だけだと、前腕の丸い端（既定の `"round"`）が手を覆い、前腕がカメラを向く姿勢で手が隠れる。`"arc"` は前腕の端を帯の境目と同じ向きの弧で切る（袖の開き口のような立体感。ツインテールのキャラはこれ）。`"flat"` は端も帯の境目もまっすぐにする。
- **前腕の影と手（`seamlessHand`）：** 前腕の影の帯は、手首側では延ばさず、手首に向かって細めて消す（`src/renderers/vector/arm.ts`）。延ばすと、手の上に重なる前腕の丸い端に影が乗り、手の中に影が入って見える。

**手の部品がないキャラの代替（描画）。** 部品のない形は、次の順で最初にある形で描く（`src/core/pose.ts` の `HAND_FALLBACK`）。どれもないときは、通常状態で表示する手を描く。

| 形 | 代替の順 |
|---|---|
| `palm` | `open` |
| `palm_up` | `palm` → `open` |
| `point`・`fist` | `open` |
| `peace` | `point` → `open` |
| `thumbs_up` | `fist` → `open` |
| `point_front` | `point`（これまでどおり） |

`peace` の代替の `point` は、`point` の左右反転の規則（人差し指が体の側に来る）に従う。ただし `point_front` は、`point` を指定したときだけ使う（`peace` の代替では使わない）。

**自動選択（ポーズに `hands` の指定がないとき）。** 手のひらの法線（T ポーズで下向き）で選ぶ。手のひらがカメラを向けば `palm`、上を向けば `palm_up`、それ以外は `open`。`palm_up` は、その手の `palm_up` 部品があるキャラだけで選ぶ（ないキャラは従来どおり `palm` か `open`）。境目でちらつかないよう、入る閾値（`palm` 0.55、`palm_up` 0.6）より、とどまる閾値（0.4、0.45）を低くしている（`src/renderers/vector/handShape.ts`）。

**手の形と体の向き。** 手の 8 種の絵はカメラから見た絵だが、モーションの `hands` の `palm` は**体の正面へ手のひらを向けた手**として書く。描画は、体の向きに合わせて、テンプレートの `side` が合う絵を選ぶ。

- 読み替えるのは `palm` だけ。`open`（平常時の手）は、体の向きにかかわらず手の甲の絵のまま描く。`palm_up` は手のひらが上を向くので、体を左右に回しても見え方は変わらない。指先の形（`point`・`fist`・`peace`・`thumbs_up`・`point_front`）は横からでも意味が読めるので、読み替えない。
- 手のひらの法線を、胸（`chest`）の左右の回転角だけで回す（お辞儀などの前後の傾きでは変えない）。ターンエンジンや体の絵の切り替えでは、子のレンダラーが体の絵の角度を除いて解いているので、その角度（`viewYaw`）を足し戻した、世界での胸の向きを使う。
- 回した法線のカメラ向きの成分（`cos`）で絵を選ぶ。手のひらが約 50° 以内でカメラを向けば `palm`（`side: palm`）、手の甲が約 50° 以内でカメラを向けば（背中を向けたとき）`open`（`side: back`）、その間は縁から見た手として `palm_up`（`side: edge`）を使う。境目でちらつかないよう、入るのは約 50°（0.64）、とどまるのは約 60°（0.5）とする（`BODY_HAND`、`bodyHandShape()`）。体の絵の切り替え（`vMorph=0`）にも、ターンエンジン（`vMorph=1`）にも、同じ判定を使う。
- 縁から見た手（`palm_up`）は、手のひら側（`_L` の絵では +x、左右反転した `_R` では −x）が、手のひらの向く画面の側（手を振る手なら顔の側）に来るように左右反転する。
- 例：体 0° と ±45° はこれまでどおり。体 ±80°・±90° の `palm` は縁から見た手になる。体 180°（背中を向ける）の `palm` は手の甲になる。
- `palm_up` の部品がないキャラは、縁の絵の代わりに、近い側の面（`palm` か `open`、90° で切り替え）で描く。
- `vHandTurn=0` で読み替えを止め、従来どおりラベルの絵をそのまま描く（比較用）。
- 9 種目の「縁から見た平らな手（手刀）」は作らず、`palm_up` を使い回す。

**検査（`check_parts.py`）。** 従来の 4 種（`open`・`point`・`fist`・`palm`）は必須（エラー）。`palm_up`・`peace`・`thumbs_up` のどれかがあれば、`point_front` を含む新しい 4 種もすべて必須（エラー）。どれもないキャラは従来の 4 種セットとして警告で通る。手首（`pivot`）から下に何も描かれていない手は警告する。

### 4.4 表にない部品

表にない部品（前髪の奥の塊 `hair_top`、手前の房 `hair_front_over` など）は、小文字のスネークケースで自由に名付けてよい。動きは名前ではなく `bone` と `layer` で決まる。頭の毛の塊は、手前に重なるほど `hair_front` に近い層にする。

### 4.5 部品数の目安

差分込みで 1 キャラ 45〜70 部品。

## 5. 補完のルール

隠れる部分も描く。動かしたときに穴が見えないことを、`qa` の `reveal`（手前の部品を隠す）と `move`（部品を支点から動かす）で確認する。

- 前髪・横髪の下の額・こめかみ・頬（`head`）。
- 耳・髪の付け根の下の頭（耳は頭の中まで伸ばす）。
- 腕を外した胴（脇の下、腕の付け根）。
- 頭の下の首、首の下の胴の上端。
- しっぽの付け根、スカートの下の脚の付け根。

## 6. 検査（`tools/vector/check_parts.py`）

```bash
.venv/bin/python tools/vector/check_parts.py <キャラID>
```

- 構造の検査：命名、必須部品、`stroke` の禁止、`bone`・`layer`・差分・表情・チェーン・腕の項目、支点の位置、`_L`・`_R` が正面図のキャラの左右（画面の右・左）にあるか。
- `tools/vector/layers/vector_layers.py validate` を通す。
- `build/` と `preview.png` を書き出し、確認画像（`var/vector/<キャラID>/check/`）を作る：通常、`qa` の各ケース、差分の一覧（目・眉・口・手・袖・表情）、部品の一覧。
- エラーが 0 件で合格。警告は内容を見て判断する。
- 確認画像には自動輪郭線と生成した腕が入らない。**最終確認はビューアで行う**（開発サーバー起動中）：

```bash
DSF=2 node tools/capture/viewer_shots.mjs var/vector/<id>/check/viewer \
  neutral="char=<id>" face30="char=<id>&framing=face&yaw=30&blink=0" faceM30="char=<id>&framing=face&yaw=-30&blink=0" \
  explain="char=<id>&motion=explain&t=1.0" spread="char=<id>&motion=spread&t=1.2" \
  half="char=<id>&framing=face&eye=half&blink=0" point="char=<id>&motion=point&t=1.5"
```

開発サーバーを 5280 以外のポートで起動したときは、`VIEWER_URL=http://127.0.0.1:<ポート>/` を付ける。

- 参照画像の座標は、目測ではなく画素を走査して測る（目・鼻・耳の位置は 15〜25px ずれやすい）。
