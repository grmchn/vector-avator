# 体と頭の回転の絵（任意）

正面の部品だけでも、頭は視差で ±30° 向き、体は平らなまま ±15° まで回せます。それより大きく向かせたいときだけ、本書の回転の絵（体 30°・60°・90°、頭 30°・60°・90°）を描き足します。

ビューアは回転の絵を既定では読みません。画面の「体と頭の回転の絵」で「使う」を選ぶか、URL に `vBody=1` を付けます。解説動画では `make_video.py --turn on`（撮影は `TURN=1`）にします。描き足す手順は `../SKILL.md` の「回転の絵（任意）」、依頼文のひな形は `tools/vector/fable_brief_body.md`・`fable_brief_head30.md`・`fable_brief_head60.md`・`fable_brief_head90.md`（左右非対称な髪のキャラは `fable_brief_head_opp.md`）です。

節の番号は部品仕様（`parts-spec.md`）の続きです。

## 7. 斜め 30° の体

体を 15° より大きく回すときは、平らな部品を回す代わりに、斜め 30° から見た体の絵に切り替える。頭・手・袖は正面の部品をそのまま使い、腕は今どおり生成する。そのため、斜めの絵として描くのは体の部品だけである。

### 7.1 ファイル

- `public/characters/<キャラID>/vector/body30.json`。`vector.json` とは別のファイルにする（`vector.json` の部品を書き換えずに追加・差し替えできるように）。
- 参照画像：`ref/body30.png`（1024×1536）。H3 の回転動画のフレーム 24（目の位置から測って約 30°）を、`front.png` と足の位置・身長が合うように拡大・配置したもの。キャラは**自分の右へ 30° 向いている**（顔が画面の左を向く）。
- 反対向き（自分の左へ 30°）は、レンダラーが左右反転して作る。体の左右の非対称（しっぽの位置など）は、反転しても成り立つように描く。

### 7.2 項目

```jsonc
{
  "format": "so-chara-vector-view/1",
  "character": "<キャラID>",
  "view": "body30",
  "yaw": -30,                   // 絵の向き（度）。+ はキャラが自分の左へ向く。ref/body30.png は -30
  "skeleton": {                 // 斜めの絵での関節の位置（キャンバス座標）
    "hips": [x, y], "chest": [x, y], "neck": [x, y], "head": [x, y],
    "shoulder_L": [x, y], "shoulder_R": [x, y], "hip_L": [x, y], "hip_R": [x, y], "ankle_L": [x, y], "ankle_R": [x, y]
  },
  "parts": [ /* 体の部品。形式は §3.1 と同じ。配列の順が描画順 */ ],
  "chains": [ /* 体の揺れ物（しっぽ・ネクタイなど）。形式は §3.4。部品の bone がチェーン id のときは必須 */ ],
  "arms": { "L": { "attach": "..." }, "R": { "attach": "..." } },   // 任意。腕を描く位置の上書き（下記）
  "order": [ /* 任意。頭の部品も含めた全部品の描画順（id の配列） */ ]
}
```

- **部品：** `vector.json` の体の部品（`layer: "body"`）と**同じ id・同じ数**で描く（部品の中の shape の数・名前は変えてよい。例：スカートのひだの本数）（`tail`、`leg_L`・`leg_R`、`torso`、`neck`、`skirt`、`collar`、`tie`、`chest_fur`、`chest_cover` など）。色・画風・塗りだけで描くこと・補完のルール（§2・§5）は正面と同じ。
- **左右：** `_L`・`_R` はキャラ自身の左右。自分の右へ向いた絵では、キャラの左（`_L`）が手前側で、画面の右寄りにある。奥側（`_R`）の脚・肩は、手前の体に一部が隠れる。隠れる部分も描く。
- **描画順：** 正面の体の部品の位置（頭の部品との前後）に、`parts` の順で入る。たとえば正面で `chest_cover` が頭より手前なら、斜めでも同じ位置に入る。部品の数や頭との前後を変える場合は、`order` に全部品の順を書く。
- **骨格の目印：** 肘・手首は書かない（腕の長さは正面の目印から測る）。肩は、参照の腕の両縁の中線を付け根まで延ばした位置とする（奥の肩は胴に隠れるので、見えている袖・腕の中線を上へ延ばす）。`head` は頭の回転の支点（あごの下、首の上端）で、頭の部品は正面の `head` との差だけ平行移動して乗せる。頭の目印は、正面の頭を平行移動して重ね、あごの下端と頭の中心の x が参照に合う位置にする。
- **腕：** 生成した腕は、`vector.json` の `arms` の `attach` の直前（裏）に描く。斜めの絵では、手前の腕（`_L`）は胴の手前、奥の腕（`_R`）は胴の裏に来るのが自然なので、必要なら `arms.L.attach`・`arms.R.attach` で左右別に上書きする（例：手前の腕は `head`＝頭の部品 `head` の直前、奥の腕は `torso`＝胴の裏）。髪・ツインテールが `head` より奥にあるキャラでは、`head` を指定した腕はそれらの手前に出る。体全体の裏に置くときは、最初の部品（例：`tail`）を指定する。
- **頭：** 描かない。頭の向きは、体の向きに首の回転を足した角度で、正面の部品の視差（§3.5）で表す。

### 7.3 切り替え（レンダラー）

- 体の向き θ（腰の左右回転）が |θ| ≤ 15° のときは正面の体を θ だけ回し、15° を超えると斜めの体を θ ∓ 30° だけ回す。平らな部品として回す量は ±15° を超えない。斜めの絵は、腰の縦の軸が正面と同じ位置に来るように横へずらして使う。
- 切り替え方は URL の `vSwitch` で選ぶ：`cut`（15° でそのまま）、`hyst`（行きは 18°、帰りは 12° で切り替え、15° 付近で止まってもちらつかない）、`fade`（15° の前後 ±4° でクロスフェード）、`fadeT`（ヒステリシスと同じ角度で切り替えを始め、`vFadeT` 秒（既定 1.0）かけて新しい絵を重ねる。不透明度は `p^vFadePow`（既定 2）で、ゆっくり始まり後半で速くなる。途中で戻ると同じ不透明度から逆向きに進む）。既定は `hyst`（ヒステリシスのみ、クロスフェードなし）。`fadeT` はオプションとして残す。
- 体の揺れ物（しっぽ）は、正面の絵の間に体の裏をすべって、15° で斜めの絵の位置に着く（`vTailSlide=0` で無効）。
- 首の部品（骨 `neck`）は、頭が向くときに上端が顎の移動量の半分だけずれ、首の付け根（`skeleton.neck`）では動かない。首の上端は顎の裏まで描かれているので、ずらさないと、頭が向いたときに顎の横からのぞく。ずらす割合は `vNeckFollow`（既定 0.5、0 で無効。1 にすると向いた側と反対で襟の上が空く）。体の向きの切り替えとは関係なく、頭の首振り全般に効く。
- 反対向きでは `body30.json` を `skeleton.hips` の x を軸に左右反転し、`_L`・`_R` を入れ替えて使う。
- `width`・`height` は書かなくてよい（キャンバスは正面と同じ 1024×1536）。参照がキャンバスの端で切れる場合も、部品はキャンバスの中に収める。
- 正面で片側に寄せて描いた部品（しっぽ）は、反転した向きへの切り替えで反対側へ跳ぶ。
- 生成した腕は、斜めの絵の肩から、世界座標の向きのまま出す（切り替えの前後で腕の向きは変わらない）。

## 8. 斜め 60°・真横 90° の体と、真横の頭

体と頭で真横（90°）まで向くために、体の絵を 30° きざみで 2 枚（`body60.json`・`body90.json`）、頭の絵を 1 枚（真横、`head90.json`）追加する。手・袖は正面の部品をそのまま使い、腕は今どおり生成する。

### 8.1 ファイルと参照画像

- 体：`public/characters/<キャラID>/vector/body60.json`・`body90.json`。形式・項目・左右・骨格の目印・腕の上書きは §7.2 と同じ（`yaw` はそれぞれ `-60`・`-90`）。
- 頭：`public/characters/<キャラID>/vector/head90.json`（§8.3）。
- 参照画像：`ref/body60.png`・`ref/body90.png`（1024×1536）。`tools/vector/sheets/turn_refs.py` が、H3 の回転動画の角度を測ってコマを選び、`turntable.sh` が H3 に渡した正方形の画像と同じ対応（正面の画素 = 2 × 動画の画素 − (256, 0)）で書き出す。回転の軸が正面の絵と同じ位置に来る。真横の頭の参照も `ref/body90.png` を使う。
- 角度の測り方：体の左右に対称に付いた目印の組（ツインテールのキャラは 2 つの髪飾り、毛の多いキャラ・仮うさぎは 2 本の耳）の画面上の間隔は D·cos θ になる。間隔が正面の半分になるコマを 60°、最小になるコマを 90° とする。H3 の回転の速さはキャラごとに違う。

### 8.2 体（`body60.json`・`body90.json`）

- §7.2 と同じく、`vector.json` の体の部品と**同じ id・同じ数**で描く。90° では奥の脚・奥の肩はほとんど手前の体に隠れるが、隠れる部分も描く（平らな部品として ±15° 回すと少し見える）。
- 腕の上書き（`arms.L.attach`・`arms.R.attach`）は、60°・90° ではほぼ必須である。手前の腕（`_L`）は胴の手前、奥の腕（`_R`）は胴の裏に描く。
- `order` を書く場合、頭の部品として正面の頭の部品の id を使う（正面の頭と組み合わせるときの順）。真横の頭と組み合わせるときは、`head90.json` の `order` が優先される（§8.3）。
- **頭の支点（`skeleton.head`）：** 60°・90° の体では、§7.2 の「正面の頭を重ねて参照に合わせた位置」ではなく、**首の上端の中央**（首の部品の上端から 40 px の範囲の左右の中央、あごの下の高さ）とする。頭が回る縦の軸の位置であり、正面の頭も真横の頭もここを支点に乗せる。体だけ横を向いて顔はカメラを向く姿勢では、頭はこの真上に来る。`check_parts.py --view` は、首の上端の中央から 8 px 以上離れると警告を出す。30° の体は、3 キャラとも首の上端の中央との差が 2 px 以内で、この約束をすでに満たしている。
- **首が見えないキャラ：** 首が胸の毛や頭に完全に隠れるキャラ（毛の多いキャラ）では、首の部品は隠れたつなぎとして、胴の上端の中心と頭の中心（耳の付け根など）の間に置き、その上端の中央を支点とする。`check_parts.py` は首の部品の制御点を含めた範囲の中央で測るので、数 px の誤差がある。
- **奥の腕の付け先（`arms.R.attach`）：** 体全体の裏に描くとき、ツインテールのキャラ・仮うさぎは `leg_R` だが、後ろ髪や耳が体の部品の間に入るキャラ（毛の多いキャラ）では、最初の体の部品（`tail`）にする。上げた奥の腕が後ろ髪の手前に出ないようにするため。
- **支点の高さ：** `skeleton.head` の y は、正面の `skeleton.head` の y にそろえる（±5 px 以内。正面の頭を乗せたとき、あごの下端が参照の頭の下端に合う高さ）。
- **揺れ物・体の部品の前後：** 参照で前後が正面と変わる部品は、参照に合わせて `order` を書く。向きごとに前後が違ってよい。ただし、参照（H3 の回転動画）が誤っていることがあるので、キャラクターシートの側面図・斜めの図と照らし合わせる。
- **仮うさぎのしっぽ：** H3 の見本（60°・75°・90°）では、丸いしっぽがお尻の横に重なって描かれていた（90° では胴の手前）。しっぽは全角度で胴の裏にあり、中心は腰の高さの背中の輪郭から、半径 × 0.8 × √sin(角度) だけ後ろに出る（側面図で約 0.8 倍、斜めの図で約 0.65 倍、正面で輪郭の際）。15°〜90° の体を直し、60°・75°・90° の見本も描き直した。ほかのキャラでも、体から突き出る小さな部品（しっぽなど）の位置は、シートで確かめる。
- **隠れた奥の目印：** 90° で隠れる奥の肩・股関節・足首は、手前側から後ろへ 6〜9 px ずらした位置に置く。
- **`seamlessWith`：** 向きごとに変えてよい。正面で線なしにした胴と脚でも、横では腹の下縁の線が要ることがある（仮うさぎの 60° では `leg_R` の `seamlessWith` を外した）。
- **正面の頭のずれ（`headOffset`、任意）：** `[dx, dy]`（px）。頭が体と同じ向きを向いたときに、正面の頭を支点からどれだけずらすと参照の頭の位置に合うか。測り方は、参照の頭の外形と、支点に乗せた正面の頭の外形について、行ごとに左右の中央を求め、その差をとる（あごの行と最大幅の行を見る）。頭の中心が首の軸より前にあるキャラでは、体と一緒に向いた頭は支点より前（顔の向く側）に出るが、頭が丸く軸の真上にあるキャラではほぼ 0 になり、符号は決まっていない。`check_parts.py` の確認画像は、正面の頭をこの分だけずらして乗せる。真横の頭はこのずれを絵の中に含むので、`headOffset` は使わない。
- ツインテールのキャラの最初の納品では、60° の `head` を正面の頭が参照に合う位置（x=455）、90° を真横の頭の首の上端（x=500）にしていて、基準が向きごとに違った。そのため、60° の体に真横の頭を乗せると約 45 px 前に出て、90° の体に正面の頭を乗せると後ろへずれた。支点を首の上端の中央（60°：473、90°：482）にそろえ、60° の参照に合わせる分を `headOffset: [-18, 0]` に分けた。

### 8.3 真横の頭（`head90.json`）

```jsonc
{
  "format": "so-chara-vector-view/1",
  "character": "<キャラID>",
  "view": "head90",
  "kind": "head",             // 頭の絵であることを示す（体の絵は省略または "body"）
  "yaw": -90,                 // キャラが自分の右へ 90° 向いた絵（顔が画面の左）
  "skeleton": {
    "head": [x, y],           // 頭の回転の支点。ref/body90.png 上の、body90.json の skeleton.head と同じ点（§8.2）
    "head_center": [x, y],    // 頭の中心（目の高さあたりの頭の球の中心）
    "head_radius": [rx, ry]   // 頭の球の半径（横・縦）
  },
  "parts": [ /* 頭の部品。形式は §3.1 と同じ。bone は "head" か頭のチェーン id */ ],
  "chains": [ /* 頭の揺れ物（耳・ツインテール・前髪）。形式は §3.4、bone は "head" */ ],
  "order": [ /* 必須。体の部品（正面と同じ id）も含めた全部品の描画順 */ ],
  "parallax": { /* 任意。真横の頭を少し回すときの層ごとの視差（§3.5）。正面の値を上書き */ },
  "headTurn": { /* 任意。§3.5 の調整値。正面の値を上書き */ }
}
```

- **見える側：** 自分の右へ向いた絵なので、見えている顔の側はキャラの左（`_L`）である。目・眉・頬は `_L` だけを描く（`eye_L_*`・`brow_L_*`・`cheek_L`）。奥の目・眉・頬（`_R`）は描かない。耳・ツインテールのように左右両方が見えるものは、奥（`_R`）も描く。
- **命名と差分：** 部品の id・`group`・`variants`・`layer`・`clipTo` は正面の部品と同じにする。目は開・半・閉と、正面にある差分（`smile`・`trouble` など）をすべて描く。口は 9 種（`closed`・`a`・`i`・`u`・`e`・`o`・`smile`・`surprise`・`trouble`）をすべて横顔で描く。眉は正面にある差分をすべて描く。表情の組み合わせ（`expressions`）は正面の `vector.json` のものを使う。
- **描画順：** 真横では、手前のツインテール・耳が首や胴の手前に、奥のものが体の裏に来るので、頭と体の前後が正面と大きく変わる。そのため `order` に、体の部品（正面と同じ id）を含めた全部品の順を書く。手・袖は書かなくてよい（腕と一緒に描く）。
- **補完：** 頭の部品は、真横の頭を ±15〜30° 回したとき（視差）にも穴が出ないように、髪の内側・顔の輪郭の裏・耳やツインテールの付け根を補完する。
- **支点：** `skeleton.head` は、`body90.json` の `skeleton.head`（首の上端の中央）と同じ点にする。真横の頭と 90° の体は同じ参照画像の上で描くので、両方を同じ値にすれば、90° の体に乗せたときに参照どおりの位置に来る。`check_parts.py --view head90` は、両者が 2 px より離れると警告を出す。
- **体の部品の前後：** `order` の中の体の部品どうしの前後は、`body90.json` の `order`（なければ `parts` の順）と同じにする。真横の頭と組むと `head90.json` の `order` が全体を上書きするので、ここでそろえないと 90° の体の前後（例：仮うさぎのしっぽは胴の手前）が崩れる。
- **shape の分け方：** 部品の id・`group`・`variants` は正面と同じにするが、部品の中の shape の名前・数は横顔に合わせて変えてよい。
- **頭の球（`head_center`・`head_radius`）：** 横顔では、額から、毛のふくらみを除いた後頭部までを頭の球とみなす。
- **省いてよい部品：** 横から見て手前の部品に重なる前髪の房（毛の多いキャラの `hair_front_mid` など）、奥の横の毛（`hair_side_R`）、そのチェーン（`bang_mid` など）は描かなくてよい。使わない前髪のチェーンは書かない。
- **耳の前後：** 向きごとに変えてよい。真横で耳の付け根が毛に溶けるキャラ（毛の多いキャラ）は、耳を頭頂の毛の手前・横の毛の裏に置き、覆う側の部品に `seamlessWith` を書く。
- **白一色のキャラの線の設計：** 全身が同じ色のキャラ（毛の多いキャラ）では、`hair_back` を穴を埋める塊とし、ほかの部品は `hair_back` と `seamlessWith` にする。線を出したい縁だけを `head`・`hair_top`・`hair_side` の上に重ね、消したい縁はそれらの外へ出す。
- **視差の確かめ方：** ビューアの `?char=<id>&renderer=V&motion=turn90_slow&t=6&yaw=-25`（体 90°・頭 65°）のように、真横の頭を回した状態を撮って見る。
- **白目の縁（`eye_<側>_ring`、任意）：** `clipTo` の切り抜きは対象部品の全 shape（縁の輪を含む）になる。横顔で虹彩が白目の前の縁に接する絵では、虹彩が縁の線を覆うので、縁の輪だけの部品を虹彩・瞳孔の手前、半目のまぶたの奥に重ねてよい（仮うさぎ）。
- **奥の揺れ物ののぞき：** 奥の耳・ツインテールを少しのぞかせる場合は、手前の部品の `seamlessWith` に奥の id を足して、のぞいた縁に二重線が出ないようにする。のぞかせる量は小さく（先端で 10 px 以下）、参照で完全に重なるなら重ねてよい。
- **耳の内側：** 横顔で耳の内側が縁の細い帯になるキャラは、`headTurn.earInner: 0` にして、内側の shape が視差で毛の外へずれないようにする（仮うさぎ）。
- **開いた口：** 横顔の開いた口は、顔の輪郭の内側（頬の上）に置く形を標準とする（ツインテールのキャラ・仮うさぎ）。あごが下がる表現は扱わない。
- **左向き：** 反対向き（自分の左へ 90°）は、レンダラーが `skeleton.head` の x を軸に左右反転して作る（`_L`・`_R` も入れ替える）。前髪の分け目など左右非対称な形は反転される。

### 8.4 切り替え（レンダラー）

- 体の向き θ に対して、置いてある体の絵（正面と `body<角度>.json`。角度は 15°・30°・45°・60°・75°・90° のうちあるもの）から最も近いものを選び、残りの θ − 絵の角度を平らな部品として回す。切り替え角は隣り合う絵の角度の中間で、30° きざみなら 15°・45°・75°（平らに回すのは ±15° まで）、15° きざみなら 7.5°・22.5°・…・82.5°（±7.5° まで）。正面と最初の絵の間は `vSwitchAt`（既定 15°）と中間の小さいほう。`vViews=30,60,90` のように、使う角度を URL で絞れる。
- 切り替えは既定でヒステリシスのみ（§7.3、2026-11-20）。比べるときは `vSwitch=fadeT` でクロスフェードに戻せる。
- 計測用に、`vBodyPin=<角度>`・`vHeadPin=<角度>` で、向きに関係なく体・頭の絵を固定できる。
- 頭の向き（体の向き＋首の回転、`chest` ではなく `head` の骨の前向き）で頭の絵を選ぶ。60° の頭（§8.5）があるキャラは、正面の頭 → 60° の頭を `vHead60At`（既定 30°）、60° の頭 → 真横の頭を `vHead90At`（既定 75°）で切り替える。60° の頭がないキャラは、`vHeadSwitch`（既定 60°）で正面の頭から真横の頭へ切り替える。
- 斜め・真横の頭は、残りの角度（頭の向き − 絵の角度）を視差で回す（上限 `vSideMaxYaw` ＋ヒステリシス、既定 30°＋3°）。正面の頭の視差の上限は、最初の頭の切り替え角＋ヒステリシス。URL の `vHeads=90` で 60° の頭を使わない比較ができる。
- **正面の頭のずれ：** 正面の頭を向きを変えた体に乗せるときは、体の絵の `headOffset` の分ずらして乗せる（`composeView`。首の付け根の支点 `skeleton.head` は動かさない）。頭が体と違う向きのときも同じ量をずらす。
- **描画順：** 頭の絵（`head60.json`・`head90.json`）の `order` が全体の順を決めるが、体の部品どうしの前後は、乗せる体の絵の順（`order`、なければ `parts` の順）に並べ直す（`withBodyOrder`）。頭の絵と違う角度の体に乗せても、体の前後が崩れない（例：仮うさぎの真横の頭を 60° の体に乗せても、しっぽは体の裏）。
- 体と頭の切り替えには、どちらもヒステリシス（`vHyst`、既定 ±3°）を付ける。`vSwitch=fadeT`（既定）では、体と頭の組み合わせが変わるたびに、新しい組み合わせの絵を 1.0 秒・加速でクロスフェードする。フェードの途中でさらに別の組み合わせへ向かうときは、前のフェードを止めずに 3 枚目として重ねる（最大 3 枚。新しい絵が不透明になった時点で下の絵を捨てる）。途中で 1 つ前の絵へ戻るときは、同じ不透明度から逆向きに進む。
- 体の絵と頭の絵の組み合わせ（例：60° の体と真横の頭）は、必要になったときに作る。揺れ物の状態と手の遅れは、切り替えのたびに前の組み合わせから引き継ぐ。

### 8.5 斜め 60° の頭（`head60.json`、任意）

真横の頭は奥の目・眉・頬を持たないので、90° の近く（75°〜90°）でしか使えない。正面の頭は ±30° までしか崩れずに回せない。その間（30°〜75°）を受け持つために、斜め 60° の頭を描く。顔の肌が頭の輪郭そのもののキャラ（仮うさぎ）では、正面の頭を 30° より先まで延ばすと後頭部がふくらみ、あごの角が突き出すので、特に必要になる。

- 形式は §8.3 と同じ（`"view": "head60"`、`"kind": "head"`、`"yaw": -60`）。参照は `ref/body60.png`。
- **奥の顔の部品：** 奥の目・眉・頬（`_R`）も描く。輪郭の縁に細く見え、視差で 30° の向きまで回すと広がるので、隠れる部分も補完する。差分（目・眉・口）は正面にあるものをすべて描く。
- **支点：** `skeleton.head` は `body60.json` の `skeleton.head` と同じ点にする。同じ参照画像の上で描くので、60° の体に乗せると参照どおりの位置に来る。斜め 60° の頭はずれを絵の中に含むので、`headOffset` は使わない（`headOffset` は正面の頭を 60° の体に乗せるときだけのもの）。
- **描画順：** `order` の体の部品どうしの前後は、`body60.json` の `order`（なければ正面の体の順）と同じにする。
- **耳の前後：** 向きごとに変えてよい。仮うさぎの 60° では、手前の耳の内側の水色が頭頂の上まで下りているので、手前の耳を頭の手前に置き（`seamlessWith: ["head"]`）、奥の耳は頭の裏のままにした。
- **白目の縁：** 白目の縁だけの部品（`eye_<側>_ring`、§8.3）は、60° でも両目に使ってよい。
- **奥の目・眉：** 奥の目は輪郭の内側に収めるのを標準とする。奥の眉は輪郭をまたいでよい（仮うさぎ）。
- **視差：** `parallax` は、正面と同じ強さを出発点にする。仮うさぎでは、Fable が付けた正面の約 1/2（`head` 0.22、`feature` 0.36）だと、30° 側へ戻しても顔がほとんど正面へ寄らず、70° 付近でも真横へ寄らなかった。正面と同じ値（`head` 0.45、`feature` 0.75）に上げた。
- **検査：** `check_parts.py <id> --view head60`（60° の体に乗せる）、`--body body30.json`（30° の体に乗せる）。視差で回した見え方は、ビューアの `motion=turn90_slow&vSwitch=hyst&t=2.25`（約 34°）〜`t=5.15`（約 77°）を撮って見る。
- 受け持ちは、正面 0°〜30°、60° の頭 30°〜75°、真横の頭 75°〜90°。
- **つなぎ目：** ヒステリシスで切り替える場合（`vMorph` なし）は、切り替えが一瞬なので、60° の頭は「視差で 30° へ戻した形が、正面の頭を 30° まで回した形」と、「75° へ進めた形が、真横の頭を 75° まで戻した形」に、それぞれ近いことが大事である。`tools/vector/head_seam.mjs` で切り替え角ちょうどの同じ姿勢を 2 つの頭で撮り、`tools/vector/head_seam.py` で頭・髪の幅と高さと中心（後ろ髪を除く `mass` と、含む `whole`。後頭部をどの部品が持つかは絵ごとに違うので、両方を見る）、耳の幅、目・鼻・口の位置、輪郭の不一致（XOR）を数値にする。目安は、幅・高さ ±5%、中心 ±3%、目・鼻・口 4%、輪郭の不一致 15% 以下（頭の幅に対する %）。
- **耳・ツインテールの付け根：** 左右一対の付け根（`ear_L`／`ear_R`、`twintail_L`／`twintail_R`）は、頭の上で円柱の表面の点のように回る。正面の頭では付け根の間隔が cos(向き) 倍になる（`headTurn.earIn`、従来どおり）。60° の頭では、その中点を軸に cos(絵の角度＋相対の向き)／cos(絵の角度) 倍になり、30° へ戻すと約 1.73 倍に開き、75° へ進めると約 0.52 倍に寄る。幅もその平方根倍にする（`headTurn.earWidthTurn`、既定 0.5。60° の頭だけに効く）。真横の頭（80° を超える絵）は描いたまま使う。60° の頭では、開く・寄せるのは id が `_L`・`_R` で終わる付け根の部品（耳・ツインテール）だけで、前髪の房などのチェーンは描いた位置のままにする（正面の頭は従来どおり、頭のチェーンすべてに cos(向き) をかける）。仮うさぎの 30° の切り替えでは、これだけで耳の幅の差が −44% から −14% に、頭まわりの輪郭の不一致が 36% から 22% に減った。
- **60° の頭の視差と調整値：** 60° の頭は、30° の向きでは顔の部品を正面寄りへ、75° では横顔の位置へ動かす必要があり、視差が正面より強くなる（毛の多いキャラは `head`・`feature` 1.3）。視差を強くするとうなずき（上下）の動きも大きくなるので、`headTurn.pitchGain` で正面と同程度に戻す（毛の多いキャラは 0.2）。30° では見えて 60° では隠れる奥の頬・横の毛は、負の視差の `hair_back` 層の別部品（例：`hair_back_R`）にしてよい。
- **中割りの鍵として描く場合：** 60° の向き（視差 0）での形が、参照の 60° のコマ・正面の頭・真横の頭と同じ画風でそのまま正しいことを最優先にする。つなぎ目の数値は参考にとどめ、形を崩して合わせない。具体的には、`skeleton.head_center` を測定値から動かさない、`parallax` を正面と同じ値から始め極端な値（0・負・1.5 など）にしない、頭の輪郭を別部品に分けない。退避：`var/vector/usagi/fable_head60_id077/head60.before_id077.json`）。

### 8.6 斜め 30° の頭

中割り（§8.7）の鍵として、正面の頭と 60° の頭の間に斜め 30° の頭を描く。依頼文のひな形は `tools/vector/fable_brief_head30.md`。

- 形式は §8.3 と同じ（`"view": "head30"`、`"kind": "head"`、`"yaw": -30`）。参照は `ref/body30.png`（H3 の 30° のコマ）。`skeleton.head` は `body30.json` の `skeleton.head` と同じ値にする。
- 部品の id・`group`・`variants`・`layer`・`clipTo`、各部品の shape の名前・数・順は、正面の頭と 60° の頭と同じにする。白目の縁（`eye_<側>_ring`）は 60° の頭にそろえて描く。
- 奥の目・眉・頬（`_R`）も描く。奥の眉は輪郭の内側に収める。
- `parallax`・`headTurn` は正面と同じ値（仮うさぎは `headTurn.earInner: 0.04` のみ 60° と同じ）。
- 正面・30°・60°・90° の頭を、同じ倍率・同じ支点で並べた画像で、目・鼻・口・耳の付け根が一方向へ滑らかに移ることを確かめる（仮うさぎ：`var/vector/usagi/fable_head30/keys.png`）。
- 検査：`check_parts.py <id> --view head30`（30° の体に乗せる）。
- 30° の頭は中割り（`vMorph=1`）のときだけ読み込む。ヒステリシスの切り替えには 30° の頭の受け持ちがない。
- 仮うさぎでは、参照の 30° の頭は正面とほとんど同じ輪郭で（半幅 0° 292 → 30° 290 → 60° 270 px）、耳は正面より立ち、手前の耳が頭の手前に来る（`order` は中割りの t = 0.5、つまり 15° で入れ替わる）。

### 8.7 中割り

体と頭を、30° きざみの鍵の絵（正面・30°・60°・90°。反対向きは左右反転）と、その間の中割りで描く。実装は `src/renderers/vector/turnEngine.ts`（鍵の管理と組み立て）と `morph.ts`（2 枚の絵の対応づけと中割り）。

- **絵の角度：** 体の向き・頭の向き（度）から、絵の角度を次のように決める。向きが `vMorphDead`（体、既定 7.5°）・`vMorphHeadDead`（頭、既定 20°）以下なら正面の絵のまま（残りは体は平らに回し、頭は視差で回す。身振りや待機の揺れで、正面の見え方が変わらない）。そこから最初の鍵（30°）までは、絵の角度が 0° から 30° へ連続して進む。その先は向きそのもの。最後に `vMorphStep`に丸める。残りの角度（±1.5° 程度）は、体は平らに回し、頭は視差で回す。
- **中割り：** 隣り合う 2 枚の鍵の、同じ id の部品の同じ名前の shape を、輪ごとに 8 px 間隔の同じ点数（40〜200 点）に打ち直し、巻き方向と始点をそろえて、点ごとに混ぜる。骨格の目印、チェーンの `root`・`tip`、`headOffset`、頭の `parallax`・`headTurn` の数値も混ぜる。`order`・`seamlessWith`・`attach` など混ぜられない属性は、近いほうの鍵から取る（t = 0.5 で切り替わる）。頭は支点（`skeleton.head`）、体は腰（`skeleton.hips` の x）を合わせてから混ぜる。
- **片方の鍵にしかない部品・shape（頭）：** 同じ `group` の部品が両方の鍵にあれば、その部品（白目を優先）の範囲に合わせて運び、ない側ではその部品の外形の上に押しつぶす（面積 0。正面にない白目の縁は、白目の輪郭から帯として現れる）。同じ group の部品がなければ、ない側の鍵へ向かう向き（顔が向く側）の端の縦線へ押しつぶす（60° の頭の奥の目は、真横の頭へ向かって横顔の輪郭へ細くなって消える）。体の絵では従来どおり近いほうの鍵から丸ごと取る。
- **消える部品の扱い：** つぶす先の縦線は、その部品がない側の鍵の頭の輪郭（`head`。shape の場合はその部品の外形）の内側に収める。つぶれていく途中で、残りが 70% を切ると薄くし始め、25% で描かなくなる（shape ごとの不透明度 `VShape.alpha`）。最初は 60° の頭の位置のまま細くつぶしたため、80〜90° で奥の目・眉・耳の内側の帯が真横の輪郭の外に細い線として残り、3° きざみの 87° と鍵の 90° を行き来するたびに出たり消えたりした。
- **小物の剛体の中割り（`VPart.morph: "rigid"`）：** どの角度から見ても同じ形の小物（仮うさぎの丸いしっぽ、ボール、バッジなど）は、形を混ぜずに、近いほうの鍵の形のまま、2 枚の鍵の範囲の間で位置と大きさだけを動かす。正面の `vector.json` の部品に書く（仮うさぎの `tail`）。
- **描き方の約束（新しいキャラ）：** 鍵の間で、部品の id、shape の名前・数・順、線の属性（`seamlessWith`・`outline`）をそろえる。1 つの shape は閉じた輪 1 つ。輪の同じ部分が、隣の鍵でも同じ側に来るように描く。描画順が入れ替わる部品は、入れ替わる角度を報告する。鍵は 30° きざみで描き、中割りを 5° ごとの静止画で確かめ、破綻した区間にだけ鍵を足す。
- **鍵のつくりの確かめ方：** `python3 tools/vector/head_keys_inventory.py <id>`（反対向きの鍵は `--opp`）で、部品ごとに各鍵の shape の名前と輪の数を一覧にする。「shape names/order differ」と「multi-ring」は 0 件にする。「missing」は、真横の頭にない奥の目・眉・頬だけにする。
- **見えない shape・部品の置き方：** 正面にある shape・部品は、見えない角度の鍵にも置く。置き方は次の 3 通り。面積 0 にはせず、わずかな幅を持たせる（巻き方向が決まらないため）。
  - 同じ色の見える shape の裏に、同じ形で重ねる（ツインテールのキャラの真横の髪飾りの 4 本の棒）。
  - 縁に沿う幅 0.3 px ほどの帯にする（真横のツインテールの内側の白・ピンク）。
  - 同じ色の部品の内側に小さく置く（毛の多いキャラの真横の前髪の細部）。後から描く部品の縁から 8 px 以上内側に置く。縁の下に入ると、自動輪郭線が新しく出る。
- **省くと崩れる例：** 顔の手前にある部品を省くと、つぶれながら薄くなる途中で、半透明の形が目に重なる。顔の手前の部品は省かずに置く。
- **正面にない shape を足さない：** 横向きの鍵だけにある細部（耳の縁の線・影、髪の筋）は、正面の同じ部品の shape のどれかに名前を合わせて、その役割を担う形として描く。または隣の shape に含めるか、やめる。毛の多いキャラの真横の耳では、`line_rim`・`shade_back` をやめたため、耳が少し平らに見えるようになった。
- **輪の配分：** 輪は弧長で等分してから、巡回シフトで重ねる。そのため、房の先・切れ込みなどの目印までの輪の長さの割合が鍵の間で大きく違うと、途中で形がつぶれたり、くさびが欠けたりする。前髪など形の込み入った部品は、隣の鍵と目印の割合をそろえる（確かめる道具の例：`var/vector/ツインテールのキャラ/fable_head30/arcs.py`・`sim.py`）。ツインテールのキャラの鍵の向きの 42〜54° の小さな白い欠けは、60° の前髪の輪の配分のずれが原因で、残している。
- **奥の揺れ物の線：** 自動輪郭線は、間に挟まる部品を考えない。頭の裏にある奥のツインテール・耳が前髪の縁と重なると、そこに線が出るので、`hair_front` の `seamlessWith` に入れる。
- **しっぽの滑り：** 中割りでは、切り替えの跳びを隠すためのしっぽの滑り（`vTailSlide`、§7.3）は使わない。正面の絵の範囲（体 7.5° 以内）では、しっぽは正面の絵の位置のまま平らに回り、その先は鍵の絵の間でしっぽの位置も中割りされる。旧方式との違いは、正面の範囲ではこの点だけである。
- **脚の向き：** 向きを変えた体の絵では、体を正面向きとして解いてから絵の角度を足しているため、脚の前後の振りがそのままでは伸び縮みに見える。脚の骨の回転を、体の絵の角度だけ縦の軸まわりに回して読み替える（`withLegsTurned`、`vLegTurn=0` で無効）。真横の絵では前後の振りが画面の中の振りになり、歩ける。正面の絵（0°）は変わらない。
- **描画エンジン：** 子レンダラーは 1 つのまま、絵の角度の組（体・頭）が変わるたびに、組み立てた部品の形・目印・チェーンの rest だけを差し替える（`VectorRenderer.swapVector`。キャンバス・骨格・揺れの状態・手の遅れ・顔の状態は保つ。チェーンは `SpringChain.rebase` で rest を移し、揺れの角度はそのまま）。中割りの形はパス文字列を経由せず、点列から直接描画用のコマンドと外形を作る。自動輪郭線用の外形（`silhouetteRings`）は、描く部品だけをそのとき計算し、組み立てた絵ごとに保持する（同じ角度へ戻ったときは再計算しない）。組み立てた絵は最大 48 組まで保持する。
- **比較用の URL：** `vMorphEngine=spawn`（角度の組ごとに子レンダラーを作る。分岐セッションの試作と同じ作り）、`vMorphEngine=proto`（さらに中割りの形をパス文字列で受け渡す）、`vMorphHead=0`（頭はヒステリシスの切り替えのまま）、`vViews`・`vHeads`（使う鍵。中割りの既定は `30,60,90`）。
- **計算量：** 1 きざみの組み立ては 2.0 ms、外形は 4.1 ms（描く 21 部品）。試作（パス文字列経由、5 px 間隔）は 13.8 ms と 23.5 ms だった。ビューアの 1 フレームの描画時間は、0°→90° の速い振り向きで平均 5.2 ms、正面の身振り（talk_demo）では 3.9 ms（組み替え前 3.8 ms）。子レンダラーの作り直しそのもの（`spawn`）は差し替えとほぼ同じで、重かったのは文字列の往復と外形の計算だった。



### 8.8 反対向きの鍵の頭

**位置づけ：** 髪のあるキャラの 0°→90° の回転は、本節の方式（キャラの右へは鍵の頭、キャラの左へは反対向きの鍵の頭を使うターンエンジン）を暫定の手法とする。髪の連続性の崩れは残っており、改善は将来の課題である。代わりに試した手法 E・Fは不採用。

鍵の頭（`head30.json`・`head60.json`・`head90.json`）は、キャラが自分の右へ向いた絵で、反対向きには左右反転して使う。左右非対称な髪のキャラ（前髪の分け目・はね毛・大きな房が片側にある）では、反転すると髪の左右が入れ替わる。そのため、正面の頭（反転しない）から反転した 30° の頭への中割りで前髪が交差し、20〜30° で崩れる。毛の多いキャラでは団子状と十字の線が、ツインテールのキャラでは小さな点が出た。こうしたキャラでは、反対向き（キャラが自分の左へ向く）の鍵の頭を、反転せずに別に描く。

- **ファイル：** `head30_opp.json`・`head60_opp.json`・`head90_opp.json`。`"view": "head<角度>_opp"`、`"yaw"` は正の値（30・60・90）。形式は §8.3・§8.5・§8.6 と同じ。依頼文のひな形は `tools/vector/fable_brief_head_opp.md`。
- **読み込み（`vectorRenderer.ts`）：** 鍵の頭と同じ角度の `_opp` があれば、反転の代わりにそれを使う。ない角度は今までどおり反転する。`vOppHeads=0` で全部を反転に戻せる（比べるとき）。体の絵は反転のまま使う（非対称な体は下の「反対向きの体」）。
- **側の名前：** 部品の id と shape の名前の `_L`／`_R` は、キャラの側を表す（キャラの右目は向きによらず `eye_R_*`）。
- **反転した鍵の shape の名前：** 反対向きの鍵がない部品（体はすべて）は、鍵を左右反転して使う。反転では、部品の id に加えて、部品の中の shape も鏡像の相手の名前に付け替える（`bodyView.ts` の `shapeMirrorMap`。正面の絵の左右対称から、襟の `flap_R`↔`flap_L`、裾の線 `hem_line_a`↔`d`・`b`↔`c` などを自動で求める。対応が取れない shape は名前の `_L`／`_R` を入れ替える）。付け替えないと、正面の絵から反転した鍵への中割りで、左右の shape が混ざって交差する。`vMirrorShapes=0` で付け替えなし。体のようにほぼ左右対称な部品は、これで反対向きの絵を描かずに済む。反対向きでは手前が `_R`、奥が `_L` になり、真横の頭には `_L` の目・眉・頬を描かない。
- **髪の左右はキャラの体に付いたまま保つ。** 左右対称な部分（輪郭・耳・目・口）は、鍵の頭を反転したものを出発点にしてよい。非対称な部分（前髪・分け目・はね毛・頭頂の跳ね毛）は描き直す。前髪の房の並びと各輪の角（アンカー）の数・順は、正面と同じにする。
- **支点：** `skeleton.head` は、反転した同じ角度の体（`body<角度>.json` を腰の x で反転したもの）の `skeleton.head` にする。体の部品どうしの `order` も、反転した体の順にする。
- **参照：** `ref/body<角度>_opp.png` は、H3 の回転動画の後半から `tools/vector/sheets/turn_refs.py <id> --other --write 30=…,60=…,90=…` で書き出す。H3 は髪もほぼ左右反転で描くので、非対称の手がかりにはならない。外形と位置の確認用に使う（頭の位置は、反転した鍵より 30〜35 px ずれることがある）。非対称な部分は、正面の絵と隣の鍵から決める。
- **検査：**
  - `check_parts.py <id> --view head<角度>_opp`：反転した体に乗せて検査する。真横では、奥の `_L` の目・眉・頬がないことを許す。
  - `head_keys_inventory.py <id> --opp`：鍵のつくりの一覧。
- **撮影：** ビューアの `motion=turn90_slow` は反対向き（キャラの左）へ、`turn90_slow_r` は鍵の向き（キャラの右）へ回る。
- **工数：** 1 キャラにつき、60°＋90° で約 12〜22 分（25〜31 万トークン）、30° で約 7〜9 分（18〜19 万トークン）。
- **反対向きの体：** 体に左右非対称な部品があるキャラ（斜めがけのかばんのキャラの斜めがけのストラップ）では、体も反転すると非対称な部品が逆の側に移り、正面から反転した体への中割りで交差する（斜めがけのかばんのキャラでは 15°〜22.5° で胸の上に黒いかたまり）。こうしたキャラでは、反対向きの体も反転せずに描く。
  - ファイルは `body30_opp.json`・`body60_opp.json`・`body90_opp.json`。`"view": "body<角度>_opp"`、`"yaw"` は正の値。形式は §7・§8.2 と同じ。
  - 読み込み：同じ角度の `_opp` があれば反転の代わりに使う（`vectorRenderer.ts`、`vOppBodies=0` で反転に戻す）。反対向きの頭の検査（`check_parts.py --view head<角度>_opp`）も、反対向きの体があればそれに乗せる。`tools/avatar/check.py` は、置いてある `_opp` の体も検査する。
  - 作り方：今ある鍵の体を腰の x で反転し（`shapeMirrorMap` と同じ shape の名前の付け替え）、非対称な部品だけを、正面のデザインのキャラの側を保って描き直す。shape の名前・数・順は正面と同じにし、隠れる shape も縁の細い帯として残す（省くと中割りで近い鍵から丸ごと取られて浮く）。依頼文の例は `var/vector/斜めがけのかばんのキャラ/fable_body_opp/brief.md`。
  - 工数（斜めがけのかばんのキャラ、Fable 5.2）：3 枚で約 19 分（24 万トークン）。
